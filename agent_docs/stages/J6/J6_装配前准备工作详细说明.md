# J6 装配前准备工作详细说明

**文档性质：** J6 阶段工程归档记录，不是实机操作手册  
**阶段：** J6 POST-ASSEMBLY COMMISSIONING 的装配前软件与证据准备  
**当前状态：** 软件基础设施准备完成，机械总装后的物理验收尚未开始  
**J5 冻结标识：** `v1.0-j5-pre-assembly-frozen`  
**记录日期：** 2026-08-22

---

## 1. J6 阶段背景

### 1.1 J5 frozen baseline 状态

J5 的定位是“装配前软件全链路与独立执行器台架验证基线”。J5 已在
`v1.0-j5-pre-assembly-frozen` 标签处冻结，作为后续工程工作的软件参考
边界。冻结内容包括：

- ROS 2 消息、topic 和节点接口；
- 六电机 UART/RS485 协议、读写安全链、批量原子性和故障处理；
- J2 六轴通信、J3 IK/执行器启动与 HOME/PARK 行为、J4 连续笛卡尔控制；
- `6pus_geometry.yaml` 作为生产几何参数唯一来源的配置契约；
- `TimedJointFeedback` 统一时间数据链路及固定延迟同步接口；
- 数值 IK/FK、解析 Jacobian、实时 FK 软件节点及其调度约束；
- 独立电缸台架上的只读通信、HOME/PARK 和控制回归证据。

J5 的 PASS 是软件和台架范围内的 PASS，并不是完整并联机构的物理精度
验收。J5 明确没有完成以下内容：完整 6PUS 机械总装、真实机构 FK 精度、
最终双 IMU 的安装外参与 lever arm、平动加速度融合、Dual-IMU/FK 融合和
ESKF 闭环。J5 中的两只 H30 IMU 仍安装在同一测试板上，不能代替装配后的
最终安装状态。

J6 的所有新增内容必须保持在该边界之外运行。装配前准备不得修改
`motor_driver_node.py`、`pus6_control`、`pus6_kinematics` 核心算法、
`6pus_geometry.yaml` 或其他 J5 冻结核心文件。

### 1.2 为什么在机械装配前必须完成 J6 准备

机械总装会引入一组台架软件无法证明的事实：六个轴的物理安装编号是否
与几何锚点对应、正方向是否一致、底位和 HOME 是否可达、连杆和球铰是否
干涉、机构几何尺寸是否等于名义值、平台运动是否协调，以及最终 IMU 的
坐标变换和杆臂参数是否正确。

如果在总装完成后才临时编写检查脚本，首次上电和首次运动会缺少统一的
入口条件、停止规则、证据格式和复核方式。这样容易出现以下工程问题：

1. 把 Mock 或独立电缸台架结果误写成真实机构验收；
2. 在轴号、方向和零位尚未确认时直接执行大范围运动；
3. 使用 CAD 名义尺寸替代装配后的实测几何；
4. 将数值 IK/FK 残差误解为真实末端定位精度；
5. 在最终 IMU 安装完成前提前进入融合或控制闭环；
6. 发生异常时无法追溯输入报告、操作者观察和阶段签字。

因此，J6 装配前准备的目标不是提前“通过”硬件，而是提前建立一个可控、
可审计、按门禁逐级开放的 commissioning 框架。所有真正依赖机构的结论
仍必须在装配后获得物理证据并由对应阶段签字确认。

## 2. 当前已完成的准备工作

以下内容按照工程目的组织，而不是按照软件批次组织。各项均已形成新增
工具、文档或测试基础，但本阶段没有执行真实硬件运动、UART 写命令或物理
标定。

### A. 硬件安全与 commissioning 准备

#### A.1 READ_ONLY 审计

**做了什么**

- 新增 `bone_ws/scripts/run_j6_phase1_readonly.py`；
- 建立只读观察时段的包装入口和统一 JSON 报告；
- 报告明确记录 `hardware_mode`、`hardware_motion_executed`、
  `hardware_write_count`、在线状态、故障和通信统计；
- 只读工具的 FakeBus/Mock 测试覆盖了零写入和异常报告路径。

**为什么需要做**

装配后的第一次上电必须先确认供电、总线和六个驱动器的静态状态，而不应
把连接确认和运动控制混在同一个入口中。只读审计为 Phase 1 提供了独立的
证据边界，也让“没有发生物理写入”成为可检查的报告字段，而不是口头声明。

**解决什么风险**

- 降低首次上电即发送目标寄存器、释放或运动指令的风险；
- 发现掉线、故障码、超时、异常电流或温度后可以在运动前停机；
- 防止把 Mock 总线活动计数当成真实硬件写入计数；
- 让后续审计可以追溯端口、波特率、时间段和原始报告。

**未来装配后什么时候使用**

在 Phase 0 机械静态检查通过、受限电源和急停准备就绪后，作为装配后第一
个带电软件入口使用。Phase 1 未签字通过前，不进入轴映射或任何运动阶段。

#### A.2 硬件连接验证

**做了什么**

- 新增 `bone_ws/scripts/check_j6_hardware_connection.py`；
- 提供端口、总线连接、六轴快照和静态设备状态的检查结构；
- 将连接结果输出为可供 Phase 1 包装器和总报告引用的证据；
- 为正常响应、超时、缺轴和报告失败情况准备 Mock 测试。

**为什么需要做**

机械装配改变了电缸、线束、接插件和 RS485 拓扑。J5 独立台架的设备路径
和在线状态不能直接推定为装配后的系统状态。连接检查必须在只读语义下独立
存在，以便先确认“系统看到了什么”。

**解决什么风险**

- 防止端口路径、波特率或总线拓扑错误被误判为机械问题；
- 防止缺少某个轴时继续执行多轴阶段；
- 防止带故障或通信不稳定的驱动器进入运动路径；
- 为报告中的轴在线率、错误码和超时提供统一来源。

**未来装配后什么时候使用**

在 Phase 1 的只读审计开始前使用，并作为 Phase 1 报告的前置证据。任何缺轴、
故障或通信不稳定都应阻止进入 Phase 2。

#### A.3 单轴 micro-jog 安全框架

**做了什么**

- 新增 `bone_ws/scripts/run_j6_phase3_single_axis_micro_jog.py`；
- 将首次运动限制为单轴、极小步数、低速和可记录的往复动作；
- 设置方向、反馈单调性、返回残差、峰值电流、故障和机械观察等报告字段；
- 在 Mock/FakeBus 下验证参数边界、单轴约束和停止/失败结果。

**为什么需要做**

Phase 3 是总装后首次允许机构产生动态运动的阶段。此时轴号、正方向和球铰
顺应性尚未由机构证实，不能直接执行全行程 HOME 或多轴轨迹。准备好的框架
把“首次运动”定义成可控的观察实验，而不是普通运动命令。

**解决什么风险**

- 防止方向定义反向导致平台或连杆朝危险方向运动；
- 防止多轴同时运动掩盖单轴接线和机械干涉问题；
- 防止位移和速度过大造成卡滞、碰撞或急停窗口过短；
- 强制记录其他轴是否保持未写入和无异常响应。

**未来装配后什么时候使用**

仅在 Phase 2 的物理 ID、拓扑和静态零位映射签字后使用。六个轴必须逐一
完成方向、反馈和间隙观察，全部通过后才允许进入 HOME/PARK。

### B. Commissioning 过程管理

#### B.1 阶段门禁清单

**做了什么**

- 新增 `agent_docs/stages/J6/J6_PHASE_GATE_CHECKLIST.md`；
- 对 Phase 0-8 定义入口条件、安全限制、必需证据和 PASS 条件；
- 定义通用停止规则：异常运动、方向错误、卡滞、干涉、异常电流、故障、
  通信丢失或停止确认失败时必须停测并记录；
- 明确 Mock、合成、回放和同板 IMU 证据不能转换为物理机构 PASS。

**为什么需要做**

J6 不是一组可以任意排列的独立脚本，而是从静态检查逐步开放运动权限的
顺序过程。清单把各阶段的“可以进入什么、不能做什么、凭什么通过”固定
下来，减少人员更替和现场压力下的解释差异。

**解决什么风险**

- 防止跳过 Phase 0-2 直接进行协调运动；
- 防止用修改限位、模式或几何文件的方式绕过失败门禁；
- 防止阶段结果只存在于口头记录而没有审查责任；
- 为停止、返工和重新评审提供共同判据。

**未来装配后什么时候使用**

从 Phase 0 机械检查开始作为全过程的主门禁文档。每个阶段只在入口、证据、
PASS 条件和签字完整后向下一阶段移交。

#### B.2 统一测试报告 schema

**做了什么**

- 新增 `agent_docs/stages/J6/J6_TEST_REPORT_SCHEMA.md`；
- 定义 `schema_version`、`tool`、`phase`、`timestamp`、`session_id`、
  `hardware_mode`、写入/运动计数、`pass`、`outcome`、门禁结果、失败原因、
  evidence、observations、metrics 和来源报告等公共字段；
- 定义无效字段不能被聚合器当作 PASS 的规则；
- 区分物理写入计数与 Mock 写入计数，并保留输入报告路径和来源关系。

**为什么需要做**

Phase 1-8 的工具输入不同：有只读快照、运动观察、实测几何、回放 FK 和
IMU 元数据。如果没有共同格式，就无法跨阶段汇总、复核或证明报告没有被
改写。

**解决什么风险**

- 防止不同工具对 PASS、HOLD、FAIL 和 NOT_STARTED 使用不同含义；
- 防止缺少必填字段的报告被误收为成功证据；
- 防止报告聚合时丢失原始路径、时间戳和失败原因；
- 支持对硬件写入和物理运动进行全局审计。

**未来装配后什么时候使用**

所有 J6 工具在现场运行或导入回放数据时均应输出该 schema。Phase 7/8 的
来源报告、Phase 6 的测量记录和操作员观察也应通过 evidence/observations
字段保留，而不是由软件擅自推断。

#### B.3 Commissioning log 系统

**做了什么**

- 新增 `agent_docs/stages/J6/J6_COMMISSIONING_LOG_TEMPLATE.md`；
- 提供 session ID、操作者、复核人、硬件序列号、软件环境、急停、电源和
  证据目录等会话级记录；
- 为 Phase 0-8 提供入口、限制、测量、证据、PASS 和签字位置；
- 记录“没有提前执行 J4 轨迹、没有将 Mock 证据当成物理 PASS、没有提前
  修改生产几何”等全局声明。

**为什么需要做**

软件 JSON 不能替代机构观察、测量工具不确定度、操作者判断和复核签字。
工程记录需要把自动指标与人工证据放在同一个 commissioning session 下，
形成可追溯的项目档案。

**解决什么风险**

- 防止物理方向、间隙、清 clearance、杆长和安装状态丢失；
- 防止报告没有对应的硬件、软件和责任人；
- 防止“工具 PASS”被误认为“阶段签字 PASS”；
- 为后续失效分析和几何变更审查保留原始记录。

**未来装配后什么时候使用**

在建立首个装配 commissioning session 时启用，并贯穿 Phase 0-8。每次停测、
偏差、返工和重新测量都应追加到同一会话或明确的新会话中。

#### B.4 汇总生成

**做了什么**

- 新增 `bone_ws/scripts/j6/generate_j6_commissioning_summary.py`；
- 只读取已有 J6 JSON 报告，输出 Markdown 汇总；
- 汇总报告包含报告数量、阶段覆盖、PASS/FAIL/STOP/INVALID 计数、每阶段
  来源路径和失败原因、缺失阶段以及报告声明的运动和写入统计；
- 明确不修改源报告、不重写时间戳、不合并掉失败来源。

**为什么需要做**

真实 commissioning 会产生多个轴报告、多个阶段报告和外部测量文件。只依靠
人工逐个打开文件容易漏掉缺失阶段或失败报告，因此需要一个不改变证据的
只读汇总视图。

**解决什么风险**

- 降低漏报失败或缺失阶段的风险；
- 保留输入报告的来源和可复核性；
- 避免汇总工具变成“改写 PASS 状态”的二次数据源；
- 便于项目评审快速识别硬件运动和写入统计。

**未来装配后什么时候使用**

在每次 Phase 0-8 会话结束或阶段性评审时使用。汇总结果只能辅助评审，
不能替代原始 JSON、物理测量、签字和阶段门禁。

### C. 机械运动验证准备

#### C.1 轴号、拓扑和静态反馈映射

**做了什么**

- 新增 `bone_ws/scripts/run_j6_phase2_axis_mapping.py`；
- 提供六轴静态反馈采集、ID 与几何锚点对应关系、底位读数和映射审查字段；
- 使用 Mock 测试验证快照收集、报告结构和缺轴/异常状态。

**为什么需要做**

J5 的六轴总线 ID 和独立台架状态不能自动证明装配后 ID1-6 与物理基座锚点
`A1-A6` 一一对应。并联机构的轴序错误会同时影响 IK、运动方向、几何参数
和后续 FK，因此必须在任何动态运动前建立静态映射。

**解决什么风险**

- 防止轴号贴签、驱动器地址和几何索引错位；
- 防止将某一轴的反馈误归属于另一根连杆；
- 防止错误的底位读数污染 HOME、几何和 FK 验收；
- 提前发现缺轴、故障或静态反馈不合理。

**未来装配后什么时候使用**

在 Phase 1 只读审计通过、机构静止且接近低位时使用。必须同时保存软件
快照、物理布置图和实测 `q_bottom`，通过审查后才进入 Phase 3。

#### C.2 HOME/PARK 验证

**做了什么**

- 新增 `bone_ws/scripts/run_j6_phase4_home_park.py`；
- 复用 J3 已验证的 homing 功能，不重写底层运动或几何算法；
- 增加 commissioning 阶段入口、HOME 基线、PARK 维护授权和结果报告；
- 为安全门禁、最终位置、故障和 Mock 总线行为提供测试。

**为什么需要做**

`OPERATING_HOME` 是 J4 控制和相对笛卡尔运动的基准，`STORAGE_PARK` 是收拢
和维护状态。台架上可达不等于总装后连杆、球铰和平台在这两个位置都可达，
必须在已确认方向后以受控方式验证。

**解决什么风险**

- 防止未确认方向就执行大行程顶升或收拢；
- 防止把 PARK 当作普通姿态控制原点；
- 防止忽略维护模式、限位、故障和反馈新鲜度门禁；
- 发现机械干涉、不到位、失平或异常电流。

**未来装配后什么时候使用**

在六轴 Phase 3 micro-jog 全部通过后使用。先建立 HOME 作为工作基线，再按
批准的维护流程验证 PARK；任何 HOME/PARK 异常都阻止进入 Phase 5。

#### C.3 小幅笛卡尔运动验证

**做了什么**

- 新增 `bone_ws/scripts/run_j6_phase5_small_cartesian.py`；
- 复用 J3/J4 已验证的 Cartesian 接口和安全包络；
- 将准备范围限制为 Z +/-2 mm、X/Y +/-2 mm、Pitch/Roll +/-0.02 rad；
- 要求 HOME 基线，并为每个小测试保留返回 HOME 的报告语义；
- 用 Mock 测试验证幅值限制、HOME 前置条件和失败状态。

**为什么需要做**

单轴方向正确不等于六轴协调正确。小幅、低速、单自由度测试可以在尚未
建立全工作空间之前，观察平台方向、连杆协调、同步、回程和早期干涉。

**解决什么风险**

- 防止过早执行全范围或 J4 连续 6DoF 轨迹；
- 防止轴号和正方向虽各自正确但联动符号错误；
- 防止 HOME 偏差、平台不平、异常电流和机械振动被掩盖；
- 为后续几何测量提供相对可信的工作基准。

**未来装配后什么时候使用**

在 Phase 4 HOME/PARK 达到稳定、水平和无干涉的条件后使用。每个批准的小
自由度测试均应独立记录并回到 HOME；通过后才进入 Phase 6 几何测量。

### D. 几何与运动学准备

#### D.1 几何测量记录框架

**做了什么**

- 新增 `bone_ws/scripts/run_j6_phase6_geometry_measurement.py`；
- 记录基座/平台锚点、半径、安装角、杆长、行程和测量不确定度等实测字段；
- 保留原始测量、重复测量、单位和来源信息；
- 使用 `bone_ws/scripts/j6_geometry_common.py` 统一输入和报告辅助逻辑。

**为什么需要做**

并联机构 FK 对杆长、锚点和安装角敏感。J5 中的 YAML 名义参数是软件基线，
不能替代总装后的实测值。测量框架把几何修订变成有来源、有不确定度、可复核
的工程数据，而不是直接编辑一个数字。

**解决什么风险**

- 防止把 CAD 理论值或经验值写成装配真值；
- 防止单次测量误差被当成几何偏差；
- 防止测量单位、坐标方向或轴序混淆；
- 防止未经评审的测量直接污染生产配置。

**未来装配后什么时候使用**

在 Phase 5 通过后、机构断电并固定于稳定测量条件时使用。测量结果先形成
候选记录，不直接覆盖生产 `6pus_geometry.yaml`。

#### D.2 候选几何加载和验证

**做了什么**

- 新增 `bone_ws/scripts/run_j6_phase6_geometry_validation.py`；
- 读取候选测量数据，检查字段、单位、几何加载和基本一致性；
- 生成候选验证报告，保留输入来源并明确是否可进入评审；
- 明确禁止自动覆盖生产 geometry YAML。

**为什么需要做**

实测几何需要在进入控制和 FK 之前经过格式、范围和内部一致性检查。候选
验证允许工程师比较实测数据与当前模型，同时保护 J5 生产配置不被临时文件
或脚本副作用改变。

**解决什么风险**

- 防止缺字段、单位错误或坐标系错误进入运动学加载路径；
- 防止候选参数尚未回归就改变运行时行为；
- 防止无法追溯某次几何验证使用的输入文件；
- 保留“候选值”和“生产冻结值”的清晰边界。

**未来装配后什么时候使用**

在 Phase 6 物理测量完成后使用。只有候选报告、误差分析和评审意见完整，
才考虑经过明确审查的生产配置更新，并重新执行完整回归。

#### D.3 IK/FK 回归验证

**做了什么**

- 新增 `bone_ws/scripts/run_j6_phase6_ik_fk_regression.py`；
- 复用现有 kinematics core 的 IK、FK 和 round-trip 接口；
- 对候选几何执行数值一致性、可加载性和回归样本检查；
- 报告中区分“数值模型自洽”与“机构物理精度”。

**为什么需要做**

候选几何即使能被 YAML loader 读取，也可能在工作空间、分支、限位或 IK/FK
闭环上出现问题。回归是候选模型进入下一阶段前的最低软件门槛。

**解决什么风险**

- 防止几何修订破坏已有 IK/FK 数值一致性；
- 防止分支保护、限位和奇异区域问题延后到硬件运动时才暴露；
- 防止把模型残差小误写成真实机构定位误差小。

**未来装配后什么时候使用**

在候选几何验证后、任何生产 YAML 变更评审前使用，并在正式变更后再次运行。
通过数值回归仍不能跳过 Phase 7 的外部真值 FK 验收。

### E. 状态观测与 FK 验证准备

#### E.1 TimedJointFeedback 链路

**做了什么**

沿用 J5 已冻结的 `TimedJointFeedback` 数据契约和时间戳链路，Phase 7 包装器
能够接收带主机时间、UART 序列和反馈状态的输入，并在报告中保留来源路径、
时间信息和状态结果。J6 没有重新实现反馈消息或修改驱动节点。

**为什么需要做**

真实 FK 验收必须把“何时采到的关节反馈”与外部位置真值对应起来。无时间
语义的静态位置数组不能支持严格的延迟、丢样本和运动期间误差分析。

**解决什么风险**

- 防止把不同时间的六轴反馈拼成一个不存在的机构状态；
- 防止通信延迟和 UART 批次信息从 FK 证据中消失；
- 防止回放报告无法追溯到原始反馈记录。

**未来装配后什么时候使用**

在 Phase 7 观察真实机构 FK 时作为反馈入口。首先完成数据采集和同步质量
审查，才能把 FK 输出与外部测量仪器进行逐时刻比较。

#### E.2 FixedLag 同步

**做了什么**

复用 J5 已验证的 FixedLag synchronizer 和严格 bracketed、zero-extrapolation
语义。`run_j6_phase7_fk_acceptance.py` 支持离线/回放/Mock 输入，报告同步
状态、等待未来样本、丢失或拒绝外推等结果，而不是创造新的同步算法。

**为什么需要做**

机械运动期间，反馈样本和 FK 查询时间通常不同。若允许无证据外推，会把时间
误差伪装成几何误差或平台运动误差。因此必须先确认时间窗内确实有可用的、被
严格夹住的反馈样本。

**解决什么风险**

- 防止外推样本被错误当作实测机构状态；
- 防止通信抖动和丢包对残差的影响被隐藏；
- 为 FK 物理验收提供可解释的同步门禁。

**未来装配后什么时候使用**

在 Phase 7 真实观测期间持续使用，并作为 FK 报告的前置质量指标。同步失败
时应停止或标记 HOLD，而不是通过修改算法参数强行形成 PASS。

#### E.3 FK acceptance framework

**做了什么**

- 新增 `bone_ws/scripts/run_j6_phase7_fk_acceptance.py`；
- 复用现有 FK node/interface、TimedJointFeedback 和 FixedLag 链路；
- 支持离线 replay/mock 验证、报告生成和输入来源保留；
- 明确 FK 为 observation-only，不连接 J4 反馈，不新增 FK 算法。

**为什么需要做**

J5-C2-SW 只证明数值模型和软件数据链路。J6 需要先把回放和证据接口准备
好，装配后才能接入外部高精度参考仪器，判断真实机构的残差、分支和稳定性。

**解决什么风险**

- 防止数值 IK->FK round-trip 被当作物理精度；
- 防止 FK 观测节点意外进入运动控制闭环；
- 防止外部真值、同步状态和 FK 输出无法关联；
- 防止在软件算法尚未稳定时把硬件误差和软件错误混在一起。

**未来装配后什么时候使用**

在 Phase 6 几何确认和回归通过后使用。Phase 7 仍需外部真值、固定的 FK
执行器配置、同步证据和签字；离线 PASS 只表示工具链可用。

### F. IMU 集成准备

#### F.1 坐标系和 frame 元数据验证

**做了什么**

- 新增 `bone_ws/scripts/run_j6_phase8_imu_preparation.py`；
- 对未来最终安装的 IMU 报告检查 frame 名称、父子关系、安装方向和元数据
  完整性；
- 在 report 的 observations/evidence 中保留安装说明和待确认项；
- 不修改 `h30_imu` 核心，不执行融合或控制。

**为什么需要做**

IMU 的数值流可以正常发布，但 frame 方向或父子关系错误时，姿态比较和
lever arm 计算仍然会错误。最终安装的 frame 不能由 J5 同板 fixture 的 frame
假设直接推导。

**解决什么风险**

- 防止 Base/Platform IMU 标签互换或轴方向解释错误；
- 防止 frame ID 缺失、重名或父子关系不明确；
- 防止后续标定结果无法关联到具体安装状态；
- 防止在元数据未确认时接入融合闭环。

**未来装配后什么时候使用**

在 Phase 8 最终支架安装完成、传感器从测试夹具迁移后使用。先完成 frame
审查，再进行外参和杆臂测量，期间保持 B4/ESKF/融合/控制关闭。

#### F.2 时间戳验证

**做了什么**

工具支持检查未来最终安装 IMU 数据的时间戳存在性、单调性、采样间隔和
关联元数据，并将异常作为报告失败或 HOLD 条件。J5 的同板时间同步结果被
作为软件能力参考，但不会被复制为最终安装证据。

**为什么需要做**

IMU 与关节反馈、FK 和外部测量必须在可比较的时间轴上。最终安装后线缆、
节点、topic overlay 或设备配置变化都可能影响时间戳语义，因此需要重新确认。

**解决什么风险**

- 防止回退到主机接收时间而丢失传感器采样时间；
- 防止时间倒退、跳变、重复或采样间隔异常；
- 防止 Base/Platform 两路数据无法对齐；
- 防止把时间错误误判成外参或机构运动误差。

**未来装配后什么时候使用**

在 Phase 8 最终安装后的静态和慢速观测中使用，并作为后续任何标定数据的
质量门槛。时间戳不通过时不进入融合验证。

#### F.3 外参与 lever-arm 记录框架

**做了什么**

- 记录最终 IMU 相对 Base、Platform 和约定参考坐标系的外参、杆臂、测量
  工具、不确定度、安装版本和证据路径；
- 生成候选报告，不自动写入生产配置或启动标定；
- 明确要求物理安装记录与软件 frame/timestamp 验证同时存在。

**为什么需要做**

lever arm 和外参依赖实际支架、基准面、紧固状态和机构姿态。J5 同板共刚体
测试只能说明相对姿态软件链路，不提供最终安装的空间变换。

**解决什么风险**

- 防止使用 CAD 估算或测试板参数代替实际安装测量；
- 防止将外参、杆臂和 frame 名称分别记录而无法关联；
- 防止未评审的 IMU 参数进入融合或控制；
- 保留测量不确定度和安装重现性证据。

**未来装配后什么时候使用**

在 Phase 7 真实 FK 通过、进入 Phase 8 且最终支架固定后使用。完成测量和
元数据审查后，才具备规划 J5-B2 后续标定的条件；本框架本身不执行当前
装置的 IMU 校准。

## 3. 当前限制与必须留到装配后的工作

### 3.1 装配前不能完成的内容

以下结论无法由现有软件、Mock、FakeBus、回放或独立电缸台架提前完成：

- 六根连杆、基座、动平台、球铰、导轨和紧固件的实际装配质量；
- 机械卡滞、干涉、关节死点、刚度、行程和真实安全间隙；
- ID1-6 与物理锚点的真实空间顺序、物理运动正方向和底位读数；
- 总装后的 HOME/PARK 可达性、平台水平度和负载/电流响应；
- 六轴协调小幅笛卡尔运动的真实方向、回程误差和振动；
- 真实基座/平台半径、安装角、杆长和行程的测量真值；
- 真实机构 `q_actual -> TimedJointFeedback -> FixedLag -> FK` 的物理精度；
- 最终 IMU 的安装刚度、frame、timestamp、外参、bias 和 lever arm。

### 3.2 必须取得的物理证据

装配后需要保留可复核的证据，而不是只保留脚本退出码：

1. Phase 0 的测量表、照片、结构和间隙检查签字；
2. Phase 1 的电源、电流、六轴在线、故障、温度、超时和零写入报告；
3. Phase 2 的物理 ID 拓扑图、静态反馈和 `q_bottom` 记录；
4. Phase 3 的每轴方向、反馈单调性、回程残差、电流和清 clearance 观察；
5. Phase 4 的 HOME/PARK 位置、水平、间隙、到位和电流记录；
6. Phase 5 的命令/反馈波形、协调运动、HOME 返回和异常记录；
7. Phase 6 的重复几何测量、不确定度、候选报告和配置评审；
8. Phase 7 的 TimedJointFeedback、同步状态、FK 输出和外部真值对比；
9. Phase 8 的最终安装照片/记录、frame/timestamp 检查、外参和杆臂测量。

上述证据必须按 session 保存，来源报告不能被汇总工具覆盖。物理观察、
方向、间隙、测量不确定度和签字属于 evidence/observations，不得由软件
自动填充为事实。

### 3.3 当前软件验证的边界

J6 新增内容已用 Mock/FakeBus/unit test 验证。根据各批次记录，J6 回归测试
共 70 项通过，Phase 8 专项测试 6 项通过，报告生成器覆盖输入读取、字段和
判定处理、缺失/无效报告、阶段聚合及源报告保护。上述结果证明工具链和
报告逻辑可用，不证明真实机构运动、真实通信质量、机械精度或 IMU 标定。

## 4. 装配后 J6 Phase 0-8 转换计划

J6 物理 commissioning 必须严格按阶段顺序执行。下一阶段的存在不构成
提前授权；只有入口条件、限制、证据、PASS 条件和复核签字全部满足，才可
开放下一阶段权限。

### Phase 0：机械静态检查

- **目标：** 在完全不上电条件下确认总装结构、连杆、球铰、导轨、机械行程、
  刚度和无干涉。
- **入口：** 机构总装完成，24 V 和 RS485 均物理断开。
- **限制：** 只允许温和人工检查，不得电机通电或使用工具强行撬动。
- **证据与 PASS：** 连杆/锚点/行程实测、照片、间隙和结构记录；无卡滞、
  松动、异常摩擦或干涉，并完成签字。

### Phase 1：电气与 UART READ_ONLY 审计

- **目标：** 确认供电、串口、六轴在线、故障、温度、电流和通信稳定性。
- **入口：** Phase 0 PASS，限流电源、急停和 by-id 端口已确认。
- **限制：** 只读；禁止 `0x25`、`0x29`、`0x1A`、HOME、PARK、J3 和 J4。
- **证据与 PASS：** 连接报告、观察时段报告和电源记录；六轴在线、故障和
  超时符合门槛，物理 `hardware_write_count` 严格为零。

### Phase 2：轴号、反馈和零位映射

- **目标：** 将 ID1-6 与物理基座锚点和软件几何索引逐一对应，记录底位。
- **入口：** Phase 1 PASS，机构静止并处于低位附近。
- **限制：** 只读查询，不发送运动或多轴写入。
- **证据与 PASS：** 物理拓扑图、静态快照、`q_bottom` 和映射复核；所有轴号
  和零位映射明确且被复核。

### Phase 3：单轴 micro-jog 方向和间隙确认

- **目标：** 首次真实运动时逐轴确认正方向、反馈单调性、回程和无干涉。
- **入口：** Phase 2 PASS，平台无额外负载，急停操作者就位。
- **限制：** 一次一个轴，20-40 steps，50 step/s，不执行全行程 HOME，不做
  多轴联动；发现反向、卡滞、异常电流或故障立即停止。
- **证据与 PASS：** 六个轴的 JSON、方向和间隙观察、残差/电流/故障记录；
  指令增加对应物理 +Z，反馈单调，返回误差不超过批准门槛。

### Phase 4：PARK/HOME 可达性和基准就位

- **目标：** 在方向已确认后验证 `OPERATING_HOME` 和 `STORAGE_PARK` 的机械
  可达性、到位、水平和间隙。
- **入口：** 六轴 Phase 3 全部 PASS，两人观察和急停安排完成。
- **限制：** 低速受控；不得跳过方向门禁；raw PARK 必须使用批准的维护授权。
- **证据与 PASS：** HOME/PARK 日志、最终位置、高度、水平、间隙、电流和故障；
  两个状态均可达、稳定、无碰撞和无异常停滞。

### Phase 5：协调小幅笛卡尔运动

- **目标：** 验证小范围 Z、X/Y、Pitch/Roll 的协调、方向、同步和返回 HOME。
- **入口：** Phase 4 PASS，平台处于 HOME，电源限制符合批准条件。
- **限制：** 仅低速小幅测试，不执行全范围或连续 J4 轨迹；每个测试后回到
  HOME，并保留命令/反馈及现场观察。
- **证据与 PASS：** 波形、位置/姿态、当前、同步、水平、间隙和预检拦截记录；
  小运动稳定、方向正确、回程满足门槛且无安全违规。

### Phase 6：最终几何测量与候选冻结

- **目标：** 用重复实测建立装配几何，验证候选配置并完成 IK/FK 软件回归。
- **入口：** Phase 5 PASS，机构断电并固定在稳定测量条件，测量工具已校准。
- **限制：** 只使用实测数据和不确定度，不使用未经证实的 CAD 猜测；生产
  YAML 只能在评审后变更，不能由 J6 工具自动覆盖。
- **证据与 PASS：** 原始测量、重复性/不确定度、候选报告、配置审查和回归
  日志；几何被接受，完整回归及规定的 IK/FK 样本检查通过。

### Phase 7：真实机构 FK 验收

- **目标：** 将真实关节反馈、严格时间同步和 FK 输出与外部真值仪器比较。
- **入口：** Phase 6 PASS，外部参考仪器就绪，FK 节点使用独立执行器。
- **限制：** FK 仅观察，不得反馈 J4 或其他运动控制；不通过修改算法或门禁
  规避残差问题。
- **证据与 PASS：** TimedJointFeedback、FixedLag 状态、FK JSON/CSV、外部真值、
  残差和分支分析；同步质量和物理精度均通过并签字。数值模型残差单独不能
  形成物理 PASS。

### Phase 8：最终 IMU 安装与 B2 准备

- **目标：** 完成最终支架安装后的 frame、timestamp、外参和 lever arm 证据。
- **入口：** Phase 7 已签署 PASS，最终支架和传感器安装完成，并移除测试板
  替代条件。
- **限制：** 不得用同板结果替代，不启动 B4、ESKF、融合或闭环控制；先完成
  lever arm 和安装记录，再讨论后续标定。
- **证据与 PASS：** 安装记录、坐标系层级、时间戳曲线、外参、杆臂、不确定度、
  慢速姿态对比和同步证据；安装刚性、元数据和几何变换可复核。

### 4.1 阶段转换的总原则

1. 任何异常运动、方向错误、卡滞、干涉、异常电流、非零故障、通信丢失或
   停止确认失败，均触发停止、断电/急停和记录，不自动进入下一阶段。
2. 不得通过修改限位、几何、维护模式或未审查配置绕过失败门禁。
3. 不得将 Mock、synthetic、replay 或同板 IMU 结果写成真实机构 PASS。
4. Phase 6 之前不改变生产几何；Phase 7 之前不宣称真实 FK 精度；Phase 8
   之前不宣称最终 IMU 外参和杆臂有效。
5. J5 冻结核心作为回归参考保持不变，所有装配相关变化必须具有独立的
   测量、报告、评审和版本来源。

## 5. 归档结论

J6 装配前准备完成了从 J5 冻结软件基线到真实 commissioning 所需的工具、

代码或 J5 冻结文件，不执行硬件，不产生物理运动授权。最终的机械、几何、
FK 和 IMU 结论必须来自装配后的现场证据与签字记录。
