# J6 Phase 3 总装 6PUS 首次运动策略设计评审

## 1. 文档目的与边界

本文件评审总装 6PUS Stewart 并联机构的首次真实运动策略。机械结构按照现有仿真 / CAD 几何制造，运动学模型、解析 IK 与 FK 不是未知项；首动阶段需要面对的是加工公差、装配误差、球铰安装误差、编码器静态偏差和零位 offset，而不是重新猜测机构拓扑。

几何标定是后续精化和冻结步骤，不是初始安全运动的唯一前置条件。首动仍必须使用当前经审查的几何模型、ID 映射和明确的局部运动包络；任何观测到的偏差只能形成待审查证据，不能在现场自动修改 `geometry.yaml`、offset 或补偿。

本文件只提供设计和门控建议：不修改代码、驱动器、`pus6_control`、`geometry.yaml` 或 J5 frozen 文件，不执行硬件，不授权本次运动。

## 3. 三层限位策略

当前硬件限位为 `[0,2000]`，软件包络为 `[0,1800]`。这两个数值不应继续作为一个未命名的“软件限位”使用，至少应分成以下三层。三层均按 ID1-ID6 分轴记录；若真实驱动返回值不同，使用分轴值而不是复制 ID1 的值。

### 3.1 硬件保护限位 `H_i`

- 当前读取到的硬件可用范围：`H_i=[0,2000]` steps（以每轴实际寄存器字段为准）。
- 这是驱动 / 电机本体的绝对保护边界，用来拒绝越界目标、诊断限位字段和保护通信路径。
- 任何 commissioning 或正常运行目标都必须位于 `H_i` 内；软件不得通过修改参数来扩大它。
- 硬件限位字段与软件安全包络必须在报告中分别保存，不能将二者混写成同一个 `limits` 字段。

### 3.2 首次调试限位 `C_i(session)`

这是一次 Phase 3 会话的临时、保守包络，不是永久配置。它应由以下交集得到：

```text
C_i(session) = H_i ∩ N_i(current) ∩ L_i(local commissioning)
```

其中 `N_i(current)` 是当前仍被接受的正常运行候选包络，`L_i(local commissioning)` 是围绕 HOME 的局部行程、IK/Jacobian、间隙和电流证据共同给出的会话窗口。建议首个笛卡尔探测只允许目标向量落在 HOME 附近的窄窗口，例如先审查 `[900,1100]` steps 的候选窗口；该数值只是现场评审起点，不得未经证据写成永久安全常数。

PARK 到 HOME 是一条单独的协调过渡路径，不能把 `C_i(session)` 简化为“从 0 到 1800 都可运动”。该路径要逐点验证目标、速度、反馈和结构间隙；PARK 的维护许可不应自动继承到笛卡尔测试。

### 3.3 正常运行限位 `N_i`

- 正常运行限位服务于日常 J4 / Cartesian 轨迹，必须比硬件保护限位更保守。
- 既有冻结基线记录的候选值为 `[200,1800]`，在当前评审中只能作为现行契约的参考，不代表已由总装实机永久确认。
- 当前 `[0,1800]` 下限允许普通运行靠近 PARK 端，且把首次调试与正常运行混在一起；不应直接解释为最终正常工作范围。
- 后续应结合实测行程、球铰角度、杆件间隙、装配零偏、IK 可行域和 Phase 5/6 证据，形成带版本和审查记录的 `N_i`。本文件不修改该配置。

**结论：** `[0,2000]` 是硬件保护层；`[0,1800]` 不能被默认视为永久正常限位，应拆分为会话级调试包络和待确认的正常运行包络。任何“放宽 1800”或“将 0 作为正常下限”的决定，都必须经过新的测量、回归和签字。

## 4. 两种首动方案比较

| 维度 | A：PARK 单执行器微动 | B：HOME 后 IK 笛卡尔微动 |
| --- | --- | --- |
| 闭链约束 | 其余五轴目标固定，改变的是一条支链长度；平台仍会通过五条支链承受反力，容易产生非预期耦合 | IK 同时生成六轴协调目标，运动约束在目标生成阶段保持一致 |
| 机械风险 | PARK 靠近收拢端，局部余量小；五轴“无写入”不等于无载荷，卡滞时内部力难以从单轴命令判断 | 首次 HOME 过渡行程较大，需单独门控；到 HOME 后有更对称的正/负行程余量和更清晰的观察窗口 |
| 双向验证 | 可以做正 / 负扰动，但每次都是局部支链诊断，不能证明平台笛卡尔方向 | 每个自由度可做正、负两个小测试，并返回 HOME，能验证方向和往返一致性 |
| IK/FK 一致性 | 无法验证 Cartesian→IK；单轴反馈不能证明 FK 姿态响应 | 可记录 IK 目标、六轴目标/实际和 FK/IMU 观测，直接检查模型一致性与装配偏差 |
| 相机 / IMU 可观测性 | 相机主要看到被选电机，平台耦合方向不明确；IMU 变化可能难以解释 | 平台微动、双 H30 相对姿态和近景相机可放在同一时间轴，证据更完整 |
| 适用定位 | 仅作为后续诊断性扰动或无法建立协调路径时的受控备选 | 作为总装首动的主策略 |

### 4.1 方案 A 的边界

方案 A 不是单电机台架测试的简单延伸。若必须采用，应先由已知 IK/Jacobian 计算与选定轴变化相容的六轴补偿向量，而不是让五轴永久固定；仍应使用最小步长、单次前进、停止观察、单独回程授权。当前 Phase3 actuator-level probe 可以保留作诊断工具，但不应作为总装首动的默认入口。

### 4.2 方案 B 的取舍

方案 B 依赖当前 CAD/仿真模型和已确认的 ID 拓扑，但这正符合现状：模型用于给出首动方向和可行目标，实机反馈用于发现零偏、装配误差和局部约束问题。它不能把模型误差“消除”，却能把误差暴露在六轴反馈、FK、IMU 和相机的同步证据中。HOME 过渡本身必须视为独立的首次协调运动，不能因为目标是 `[1000]*6` 就跳过观察。

**策略选择：推荐 B。** A 仅作为有明确诊断目的、单独审批的后备路径。

## 5. 推荐 J6 实际过渡序列

```text
STORAGE_PARK
    ↓ 只读基线 / 限位与安全门
协调、低速、单次 HOME 过渡
    ↓ HOME 静态确认
笛卡尔微动：单自由度、正负分开、每次回到 HOME
    ↓ 全部观察与反馈通过
返回 HOME（单独授权）
    ↓ 记录最终 HOME
返回 STORAGE_PARK（维护授权、单独记录）
```

### 5.1 PARK → HOME

1. 断言六轴 ID 映射、`q_park` 反馈、硬件 `H_i`、电源限流、急停和双人观察均已记录。
2. 预先用现有 IK/轨迹接口生成从当前反馈到 `OPERATING_HOME` 的六轴协调目标；检查每个中间目标不越过 `H_i`，并记录是否经过会话限位 `C_i(session)`。
3. 使用已审查的 HOME runner，低速、单周期、无自动重试；任何轴 fault、电流异常、反馈不跟随、平台偏斜或间隙缩小时立即停止。
4. 到达 `[1000]*6` 后保持，记录六轴残差、平台高度/水平、球铰角度、线缆和相机/双 H30 基线。HOME PASS 只表示“到达且观察无异常”，不表示几何已标定。

### 5.2 HOME 后的笛卡尔微动

每个测试都从已确认 HOME 开始，目标为一个自由度，完成“目标预览 → 一次前进 → 观察保持 → 单独授权返回 HOME”。不允许在一次命令中叠加多个自由度，不允许连续自动循环。

建议的首轮顺序：

| 顺序 | 测试 | 首轮建议 | 通过后可考虑 |
| ---: | --- | --- | --- |
| 1 | `Z+` | 极小正向位移（建议先从 0.25–0.5 mm 级别开始） | 对称 `Z-` |
| 2 | `Z-` | 与 `Z+` 相同幅度，返回 HOME 后再做 | X/Y 平移 |
| 3 | `X+` | 0.25–0.5 mm，检查侧向间隙 | `X-` |
| 4 | `X-` | 0.25–0.5 mm | Y 方向 |
| 5 | `Y+` | 0.25–0.5 mm | `Y-` |
| 6 | `Y-` | 0.25–0.5 mm | Roll/Pitch |
| 7 | `Roll+` / `Roll-` | 先用约 0.25°（0.0044 rad）级别 | 约 0.5°级别 |
| 8 | `Pitch+` / `Pitch-` | 先用约 0.25°（0.0044 rad）级别 | 约 0.5°级别 |

上述位移和角度是首轮审查建议，不是当前代码参数，也不是授权值。实际写入前必须检查每轴 IK 步进增量；若任何单轴增量超出已批准的 commissioning 窗口，应缩小 Cartesian 目标并重新审查，不能靠限位裁剪或发送部分目标。

不建议首轮测试 `Yaw`，除非平台/球铰视野、Jacobian 条件、杆件间隙和现场授权另有明确证据。每个正向测试完成并记录后，才进行对应负向测试；不要用自动回程掩盖正向观察结果。

### 5.3 返回 HOME → PARK

- 每个 Cartesian 测试的返回 HOME 是独立授权事件；核对六轴残差和观察字段后才执行。
- 全部测试结束后，先记录最终 HOME 静态证据，再由维护授权人单独批准 HOME → PARK。
- PARK 仅用于收拢 / 断电保持，不作为笛卡尔控制参考；返回 PARK 后再次读取六轴状态并确认无 fault、无残余写入。

## 6. 必须满足的安全门

### 6.1 运动前硬门

- Phase 0、Phase 1、Phase 2 记录和签字可追溯；ID1=A1 至 ID6=A6 不变。
- 六轴只读基线完整：target/actual/raw、current、fault、temperature、硬件限位、时间戳和 `hardware_write_count=0`。
- `q_park` 观测值与软件 PARK 参考分开记录；机械 bottom、球铰角度、杆件和线缆间隙有现场记录。未确认时保持 `HOLD`，不得用“几何已知”替代机械观察。
- HOME 目标明确为 `[1000]*6`；目标预览、IK 成功、FK 回算和每轴步进量均可审计。
- 所有目标位于 `H_i` 和会话 `C_i(session)` 内；正常运行 `N_i` 的状态必须明确，不能把 `[0,1800]` 当成默认永久范围。
- 电源限流、急停、机械观察位、近景相机、双 H30 时间戳和两人职责已就位。

### 6.2 单次微动硬门

- 一次只允许一个 Cartesian 自由度，正负方向分别授权；初始幅度小于后续工作幅度。
- IK 产生六轴协调目标，禁止单轴固定腿替代；目标轨迹不包含 HOME/PARK/IK 之外的隐藏动作。
- 禁止自动重试、自动扩大步长和无条件自动返回；异常只进入 `STOP/HOLD`。
- 每个反馈周期记录六轴 target/actual/current/fault/temperature、反馈时间、写审计、FK 结果、双 H30 相对姿态和相机时间戳。
- 任一 fault、异常电流、反馈发散、平台方向错误、球铰接近死挡、杆件/线缆干涉、异响或急停失败，立即停止并保持 HOLD。

### 6.3 通过条件

首轮 Cartesian 测试只有在以下全部满足时才可标记 PASS：

1. 正向和负向平台响应与目标自由度一致，且没有可见耦合异常；
2. 六轴实际位置按预期跟随，停止后无持续漂移，返回 HOME 残差在预先批准的步数内；
3. fault 全 0，电流 / 温度没有超出批准阈值，通信和时间轴连续；
4. 球铰、杆件、线缆和邻近结构无干涉、卡滞、死挡或异常声响；
5. FK/IK 目标差异、双 H30 相对姿态和相机证据均可追溯；
6. 写审计只包含预期的协调目标写入，`unexpected_writes=0`。

任一项缺失均为 `HOLD`，不是“部分 PASS”。

## 7. 观测和证据要求

每个事件段必须单独记录 `baseline_static`、`forward_perturbation`、`observation_hold`、`return_home_authorized` 和（最终）`park_authorized`。至少包含：

- 六轴 target/actual/raw、current、fault、temperature、逐轴反馈时间；
- IK 输入姿态、IK 输出目标步数、每轴目标增量和硬件/调试/正常三层限位判定；
- FK 回算姿态、目标—实际误差和条件数 / 奇异性告警（如接口提供）；
- 基座与平台 H30 原始样本、`base_to_platform` 相对姿态、样本配对误差和时钟域；
- 相机快照主机单调时间戳、帧 ID、可见支链和遮挡说明；
- 操作员对平台运动、球铰状态、干涉、异响、急停和电流变化的签字字段。

人工观察和软件反馈必须使用同一 `session_id` 和单调时间轴；不能用模型预测替代实机观察，也不能用相机看不到 ID1 解释为 ID1 无风险。

## 8. 现有 Phase3 工具的处置建议

### 8.1 不建议直接使用现有 actuator-level probe 作为主首动工具

`run_j6_phase3_first_motion_probe.py` 的状态机、步长白名单、显式回程授权和写审计仍有价值，但它的基本动作是单轴目标写入，不能生成闭链一致的 Cartesian 目标，也不能验证平台自由度或 IK/FK 一致性。因此它应降级为：

- 仅在有明确诊断问题、已批准补偿向量和独立机械观察的情况下使用；
- 不作为 PARK 状态下总装机构的默认 first motion；
- 不因“其余五轴零写入”而降低安全门。

### 8.2 推荐扩展而非重写底层控制

J6 需要一个新的上层 commissioning 编排层（或扩展现有 Phase 5 wrapper），复用既有 IK、轨迹整形、驱动 preflight 和 FakeBus/实机显式授权接口，增加：

1. `PARK → HOME` 独立阶段和两人观察门；
2. 运动前 Cartesian 目标预览、IK/FK 回算、每轴步数和三层限位报告；
3. 单自由度正/负测试、返回 HOME 单独授权、无自动重试；
4. 六轴 + FK + 双 H30 + 相机时间轴的统一 JSON 证据；
5. 事件级 `STOP/HOLD`、电流/故障/间隙/异响人工字段和 unexpected write 审计。

底层 `motor_driver_node.py`、`pus6_control`、J5 frozen 接口和 `geometry.yaml` 均不需要因本评审而改动。是否实现新编排工具，应另立软件变更任务并先补充 Mock/FakeBus 测试。

## 9. 推荐结论

| 决策项 | 结论 |
| --- | --- |
| 首动主策略 | **B：协调 HOME 后的 Cartesian micro-motion** |
| A 单执行器 PARK 微动 | 仅诊断备选，非默认首动 |
| 当前 `[0,2000]` | 硬件保护边界，必须始终保留 |
| 当前 `[0,1800]` | 未命名的混合包络；不能假定永久正确，应拆分并重新审查 |
| 首轮自由度 | `Z+ → Z- → X+ → X- → Y+ → Y- → Roll± → Pitch±` |
| 首轮幅度 | 先 0.25–0.5 mm、约 0.25°级别；每次回 HOME 后再做下一项 |
| HOME / PARK | 均为独立授权阶段；PARK 只用于最终收拢/断电 |
| 几何标定 | 后续 Phase 6 精化，不阻止使用已审查模型进行保守首动；不允许首动现场自动改参 |
| 当前授权 | **HOLD：本文件不授权硬件运动** |

本评审的 PASS 只表示策略设计完成。实际 J6 Phase 3 必须在上述门控和现场签字齐全后另行授权；任何异常只报告并保持 `HOLD`，不得尝试恢复运动。
