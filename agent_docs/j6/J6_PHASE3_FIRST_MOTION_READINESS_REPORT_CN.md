# J6 Phase 3 首次运动就绪性审计报告

## 1. 审计范围与结论

本报告仅审计 J6 Phase 3 首次闭链运动的**软件准备、证据字段和现场门控**。本次没有打开硬件、没有发送电机命令、没有运行探测器，不改变任何控制或运动行为。

**总体结论：`HOLD`。**

探测器的运动策略约束和观测记录格式已具备审计条件，但当前不能授权 ID4 `+2 steps` 首动，原因是机械 bottom 基线、当前负位置反馈与软件包络的关系，以及本次双 H30 实时证据仍未完成闭合。`ID4` 仅被记录为首个观察候选，不构成运动授权。

## 3. 探测器静态审计

审计对象：[run_j6_phase3_first_motion_probe.py](../../bone_ws/scripts/run_j6_phase3_first_motion_probe.py)。

### 3.1 安全行为核对

| 审计项 | 结果 | 依据 / 边界 |
| --- | --- | --- |
| 不执行 HOME | 通过 | 脚本只使用单轴目标寄存器路径，没有 HOME 调用 |
| 不执行 PARK | 通过 | 没有 PARK 调用；报告固定记录 `park_executed=false` |
| 不执行 Cartesian motion | 通过 | 没有 IK、Cartesian 或多轴目标接口调用 |
| 不自动回程 | 通过 | `observation_hold()` 明确 `automatic_return=false`；默认 `return_authorized=false` |
| 显式回程授权 | 通过 | 只有保持阶段完成且操作员字段全部安全时，`authorize_return()` 才能写回基线 |
| 步长限制 | 通过 | `abs(displacement_steps)` 仅允许 `{2,5,10}`，默认 `2` |
| 目标写入范围 | 通过 | 前进和回程各最多一个选定轴目标写入；未选轴不发送运动写入 |
| 自动重试 | 通过 | 构造器要求 `controller.retries=0`；命令失败不重试，允许的暂停只属于安全停止记录 |
| 写审计 | 通过 | 保存 `write_audit`、目标写入计数和 `unexpected_writes`；物理与 Mock 写入分开 |
| 六轴反馈 | 通过 | 基线、前进后反馈、保持样本和回程反馈均序列化六轴字段 |

### 3.2 探测器状态机

```text
CREATED
  -> BASELINE_RECORDED
  -> FORWARD_COMPLETE
  -> OBSERVATION_HOLD
  -> (显式授权) RETURN_COMPLETE
```

异常路径进入 `FAILED` 或 `STOPPED`，不会自动反向、增大步长或重复目标。默认调用在 `OBSERVATION_HOLD` 结束，报告为 `HOLD`，不产生回程写入。

### 3.3 当前基线阻断项

探测器的 `record_baseline()` 除了检查 fault/current，还要求六轴当前实际位置全部位于软件包络 `[0,1800]`。当前已知观测值中的 ID3=`-2`、ID4=`-1` 不满足该门，因此即使选定 ID4、目标方向为正、理论目标为“基线加 2 steps”，探测器也会在基线阶段阻止运动。

该阻断不能通过修改限位、offset、几何或绕过检查解决。应由机械 / 协议审查明确原始负值的语义，并形成批准的 Phase 3 基线证据后再决定是否允许工具进入前进阶段。本报告不修改软件行为。

### 4.2 记录器就绪边界

当前记录器是文档和离线模板，不是已经运行的实时采集节点。因此：

- 字段设计和证据分级：可审计；
- 本次会话的双 H30 样本、相对姿态、配对误差和相机时间戳：尚无证据；
- 记录器本身不会产生 `hardware_write_count`，模板固定为 `offline`、`false`、`0`；
- 记录器 PASS 只能表示证据文件完整，不能表示机构运动安全 PASS。

## 5. 报告完整性要求

一次有效的首次运动报告必须同时包含以下四个事件段：

### 5.1 `baseline_static`

- 六轴 target/actual/raw steps、current、fault、temperature；
- 六轴扫描起止和逐轴反馈时间戳；
- 两路 H30 原始样本和各自时间字段；
- 相机启用时的初始帧时间戳；
- 当前软件参考、实测反馈和机械状态说明。

### 5.2 `forward_perturbation`

- 选定轴 `ID4`、正方向、批准步长 `+2` 的事件标记；
- 前进命令时间、目标、前进后六轴反馈；
- 六轴 current/fault/temperature 和写审计；
- 平台、球铰、干涉、异响人工观察。

### 5.3 `observation_hold`

- 不自动回程的保持区间起止时间；
- 连续六轴反馈样本；
- 两路 IMU 相对配对和相对姿态有效性；
- 相机可见范围和时间戳；
- 任何异常必须保留原始样本并标记 `HOLD`/`STOP`。

### 5.4 `return_authorized`

- 仅在现场确认后记录授权人、时间和理由；
- 回程目标和六轴反馈；
- 回程残差、current、fault 和停止确认；
- 回程目标写入和完整写审计。

没有实际运行时，这四段只能保持模板的 `null` / `NOT_STARTED`，不得预填成 PASS。

## 6. 剩余风险与未关闭门

1. **机械 bottom 未确认。** 之前的 Phase 2 人工记录仍将机械 bottom 标为待确认；当前 `STORAGE_PARK` 参考和 `q_park observed` 不能替代 `q_bottom`。
2. **负位置与软件包络冲突。** ID3=`-2`、ID4=`-1` 会触发探测器的全轴基线包络门；现有硬件/软件字段差异必须在不改代码的情况下完成批准解释。
3. **闭链内部载荷未知。** ID4 单轴扰动时 ID1/ID2/ID3/ID5/ID6 虽无运动写入，仍可能承受平台约束反力；零写入不等于零受力。
4. **ID4 正方向仍需现场观察。** 软件不能推断平台 `+Z`、侧倾或其他耦合响应；ID4 只是一根首选观察轴。
5. **相机视野不完整。** ID2-ID6 可见，ID1 不在主视野；相机不能替代六轴反馈和平台 / 球铰观察。
6. **双 H30 实时证据缺失。** 当前只有离线字段和模板；实际 frame、话题、时间连续性、外参来源和 `base_to_platform` 配对尚未形成会话证据。
7. **几何与零位仍受门控。** 不能利用首动数据自动修改 `geometry.yaml`、offset 或位置补偿，也不能把观测结果直接升级为 Cartesian/IK 结论。

- [ ] 近景相机已写入会话 manifest，确认 ID4 可见并记录可用时钟域。

- [ ] 记录器只做被动采集；运动工具的回程选项默认关闭。

### 7.2 前进与保持

- [ ] 仅选择 ID4，单向 `+2 steps`，不扩大为 5/10 steps。
- [ ] 前进后进入人工观察保持，不自动回程、不重试、不改变目标。

- [ ] 任何方向错误、卡滞、异常电流、fault、异响、干涉或时间失序均立即 `STOP/HOLD`。

### 7.3 回程授权

- [ ] 只有前进与保持观察全部安全，且四项人工字段完整为安全值时，才填写回程授权。

- [ ] 回程残差、fault/current、停止状态和相机/IMU时间段已记录。
- [ ] 会话结束后原始流、索引、报告和校验和均已保存，不覆盖既有证据。
