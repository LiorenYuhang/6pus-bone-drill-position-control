# 因时微型伺服电缸 Modbus RTU 多电机控制方案

> 方案目标：使用因时官方 AED-LA-92-12MR1 Modbus RTU 转换器，通过 RS485 总线同时控制 **6 个** LAF50-024D 微型伺服电缸。
>
> 编写日期：2026-06-10

---

## 1. 背景与问题

### 1.1 现有方案（单电机）

```
PC (USB) ── USB-TTL (LVTTL 3.3V) ── 电机
```

- 物理层：LVTTL 点对点，一个 USB-TTL 模块只能接一个电机
- 协议层：因时自定义二进制协议（问答式，帧格式 `0x55 0xAA | Length | ID | CMD | RegAddr | Data | Checksum`）
- 协议支持多电机寻址（motor_id 1~254），但物理层限制了只能一对一连接
- 控制 6 个电机需要 6 个 USB 口 + 6 个 USB-TTL 模块 + 6 根线

### 1.2 目标方案（6 电机 RS485 总线）

```
                              ┌── AED-LA-92-12MR1 #1 (addr=01) ── 电机 #1
                              ├── AED-LA-92-12MR1 #2 (addr=02) ── 电机 #2
PC ── USB-RS485 ── RS485 总线 ─┼── AED-LA-92-12MR1 #3 (addr=03) ── 电机 #3
                    (A/B/GND) ├── AED-LA-92-12MR1 #4 (addr=04) ── 电机 #4
                              ├── AED-LA-92-12MR1 #5 (addr=05) ── 电机 #5
                              └── AED-LA-92-12MR1 #6 (addr=06) ── 电机 #6
```

- 物理层：RS485 差分总线，所有转换器并联在两根线（A/B）上
- 协议层：Modbus RTU，通过从站地址区分不同电机
- 只需 **1 个 USB 口** + **1 根 4 芯线缆**（A/B/GND/24V）串联所有转换器

## 2. AED-LA-92-12MR1 转换器详解

### 2.1 产品信息

| 项目 | 参数 |
|------|------|
| 型号 | AED-LA-92-12MR1 |
| 尺寸 | 110 × 50 × 24 mm |
| 功能 | RS485 (Modbus RTU) ↔ LVTTL 3.3V (因时自定义协议) 双向转换 |
| 内置 MCU | 协议解析与转换，24V→8V 降压模块 |
| 数量需求 | **每个电机配 1 个**（共需 6 个） |

### 2.2 转换器两侧通信参数

| 参数 | Modbus 侧 (RS485) | 电缸侧 (LVTTL) |
|------|-------------------|-----------------|
| 物理接口 | RS485 (A+/B-/GND) | 4pin 杜邦 (GND/VCC/TX/RX) |
| 协议 | Modbus RTU | 因时自定义二进制协议 |
| 波特率 | 9600 bps（默认，最高可设 115200） | 921600 bps（必须匹配电缸出厂设置） |
| 数据位 | 8 | 8 |
| 校验位 | Even | 无 |
| 停止位 | 1 | 1 |
| 供电 | 24V DC / 1A 输入 | 输出 8V DC / 2A 给电缸 |
| 功能码 | 0x03(读), 0x06(写单个), 0x10(写多个) | — |

### 2.3 转换器接线端定义

**左侧（连接上位机/RS485 总线）：**

| 端子 | 信号 | 说明 |
|------|------|------|
| GND | 地 | 共地 |
| 24V_in | 电源输入 | DC 24V / 1A |
| A+ | RS485 差分正 | 所有转换器 A+ 并联 |
| B- | RS485 差分负 | 所有转换器 B- 并联 |

**右侧（连接电缸）：**

| 端子 | 线色 | 信号 | 说明 |
|------|------|------|------|
| GND | 黑 ■ | 地 | 接电缸 GND（pin1） |
| 8V_out | 红 ■ | 电源输出 | 接电缸 VCC（pin2） |
| TX | 黄 ■ | 3.3V 串口发送 | 接电缸 RXD（pin3） |
| RX | 蓝 ■ | 3.3V 串口接收 | 接电缸 TXD（pin4） |

## 3. Modbus RTU 寄存器映射

### 3.1 完整寄存器表

| 地址 | 名称 | 范围 | 功能 | 读写 | 生效时机 |
|------|------|------|------|------|----------|
| **0x0001** | CMD-ID | 1~254 (0x01~0xFE) | 从站地址 | R/W | 立即 |
| 0x0002 | CMD-BAUD | 1200~115200 | 通信波特率 | R/W | 重新上电 |
| 0x0003 | CMD-SAVE | 0 / 1 | 保存参数到 Flash | R/W | 重新上电 |
| 0x0004 | CMD-SET-0N | 0 / 1 | 设当前状态为力基准值 | R/W | 立即 |
| **0x0010** | CMD-STOP | 0 / 1 | 急停 | R/W | 立即 |
| 0x0011 | CMD-RESTART | 0 / 1 | 恢复运行 | R/W | 立即 |
| 0x0012 | CMD-FAULTACK | 0 / 1 | 清除故障 | R/W | 立即 |
| **0x0014** | CMD-SETVEL | 1 ~ Vmax (步/s) | 速度控制参数 | R/W | 立即 |
| **0x001F** | CMD-SETFORCE | -15000 ~ +15000 (g) | 力控目标值 | R/W | 立即 |
| **0x0020** | CMD-SETPOS | 0 ~ 2000 (步) | 目标位置 | R/W | 立即 |
| 0x0021 | CMD_CURPOS | -100 ~ 2100 | 当前位置（只读） | R | — |
| 0x0022 | CMD_CURTEMP | -20 ~ 100 (℃) | 当前温度（只读） | R | — |
| 0x0023 | CMD_CURCUR | 0 ~ 2000 (mA) | 当前电流（只读） | R | — |
| 0x0024 | CMD_CURERR | 故障码（见下表） | 故障码（只读） | R | — |
| 0x0025 | CMD_FORCE | -15000 ~ +15000 (g) | 实际受力值（只读） | R | — |

### 3.2 故障码定义

| 值 | 含义 |
|----|------|
| 0x0001 | 堵转保护 |
| 0x0002 | 过温保护 |
| 0x0004 | 过流保护 |
| 0x0008 | 电机异常 |

**接线要点：**
- RS485 总线采用**手拉手菊花链**拓扑，不要星形分支
- A+ 全部并联，B- 全部并联，GND 全部并联
- 总线两端各接一个 **120Ω 终端电阻**（如果总线长度 > 2m 或波特率 ≥ 115200）
- 24V 电源走总线给每个转换器供电（注意线径，长距离需考虑压降）
- 每个转换器到其对应电缸：4 根杜邦线（GND黑/VCC红/TX黄/RX蓝）

### 4.3 上电前检查清单

- [ ] 每个转换器的 Modbus 从站地址已设为不同值（1~6）
- [ ] 所有电缸波特率为出厂默认 921600
- [ ] RS485 总线 A/B/GND 接线正确，无短路、无反接
- [ ] 24V 电源正负极正确
- [ ] 电缸到转换器的 4pin 线序正确（GND黑/VCC红/TX黄/RX蓝）
- [ ] 严禁带电插拔

## 5. 通信性能分析

### 5.1 Modbus RTU 帧时序

以写单个寄存器（功能码 0x06）为例：
- 请求帧：8 字节
- 应答帧：8 字节
- 帧间隔：≥3.5 字符时间

**一帧完整通信的数据量 ≈ 20 字节（含帧间隔和转换器内部处理延迟）**

### 5.2 不同波特率下的性能

| 波特率 | 单帧耗时 | 6 电机轮询周期 | 单电机有效更新频率 | 是否满足伺服模式 (≥50Hz) |
|--------|---------|---------------|-------------------|--------------------------|
| **9600**（默认） | ~25ms | **~150ms** | **~6.7 Hz** | ❌ 严重不足 |
| 19200 | ~13ms | ~78ms | ~12.8 Hz | ❌ 不足 |
| 38400 | ~7ms | ~42ms | ~23.8 Hz | ❌ 不足 |
| 57600 | ~5ms | ~30ms | ~33.3 Hz | ❌ 勉强不足 |
| **115200**（推荐） | **~3ms** | **~18ms** | **~55.6 Hz** | ✅ 刚好满足 |

### 5.3 结论

- **必须将波特率从 9600 改为 115200**，否则 6 个电机的伺服模式无法工作
- 115200 bps 下，6 电机轮询可达 ~55 Hz，满足伺服模式最低 50 Hz 的要求
- 如果应用不需要伺服模式（只用定位/速度/力控模式），9600 bps 也够用
- RS485 总线的物理极限：115200 bps 下推荐总线长度 < 100m

## 6. 与原方案的对比

| 维度 | 原方案 (USB-TTL) | 新方案 (Modbus RTU + RS485) |
|------|-----------------|---------------------------|
| **物理连接** | 6 个 USB 口 + 6 根 USB 线 | 1 个 USB 口 + 1 根 RS485 总线 |
| **布线复杂度** | 高（星形拓扑，每电机一根线到 PC） | 低（菊花链，一根线串所有电机） |
| **通信协议** | 因时自定义二进制协议 | Modbus RTU 标准协议 |
| **通信速率** | 921600 bps | 9600~115200 bps（瓶颈在 Modbus 侧） |
| **伺服模式频率** | 单电机 ≥50Hz 无压力 | 6 电机轮询 ~55Hz (115200bps) |
| **代码兼容性** | 已有完整代码 | 需要重写通信层 |
| **硬件成本（增量）** | 0（已有） | 6×转换器 + 1×USB-RS485 + 24V电源 |
| **可扩展性** | 每增加一个电机多一根 USB 线 | 总线上直接加节点（最多 32 个） |
| **抗干扰能力** | 弱（LVTTL 单端信号） | 强（RS485 差分信号） |
| **PLC 兼容性** | 不支持 | ✅ 可直接接入标准 PLC/工控系统 |

## 7. 软件改造要点

### 7.1 现有代码架构

```
insmotor_driver/
├── protocol.py          # 因时自定义协议（需要重写）
├── motor_controller.py  # 高层控制接口（可复用接口设计）
├── motor_node.py        # ROS2 交互节点（需要适配）
```

### 7.2 改造计划

**通信层（protocol.py → modbus_protocol.py）：**
- 替换 pyserial 为 `minimalmodbus` 或 `pymodbus`
- 替换因时自定义帧打包/解包为 Modbus 寄存器读写
- 新增从站地址参数替代 motor_id

**控制层（motor_controller.py → modbus_motor_controller.py）：**
- 保持相同的 API 风格：`move_to_position()`, `read_status()`, `set_force_mode()` 等
- 内部实现改为 Modbus 寄存器操作
- 新增接口：`set_slave_address()`, `set_baudrate()`

**ROS2 节点（motor_node.py）：**
- 适配新的控制器类
- 可保持相同的交互模式

### 7.3 Python 依赖变化

```diff
- pyserial
+ minimalmodbus  (推荐，轻量，API 简洁)
+ 或 pymodbus    (功能更全，较重)
```

## 8. 控制模式映射

因时自定义协议有 6 种控制模式，Modbus 转换器通过不同寄存器来实现：

| 控制模式 | 原协议实现 | Modbus 实现 | 备注 |
|----------|-----------|-------------|------|
| **定位模式** | 写 CONTROL_MODE=0, 写 POSITION_TARGET | 写 CMD-SETPOS (0x0020) | 直接写位置即触发定位 |
| **伺服模式** | 写 CONTROL_MODE=1, ≥50Hz 写 POSITION_TARGET | 高频写 CMD-SETPOS (0x0020) | 需 115200 bps |
| **速度模式** | 写 CONTROL_MODE=2 + SPEED + POSITION | 写 CMD-SETVEL (0x0014) + 写 CMD-SETPOS (0x0020) | — |
| **力控模式** | 写 CONTROL_MODE=3 + FORCE_TARGET | 写 CMD-SETFORCE (0x001F) | 仅力闭环型支持 |
| **电压模式** | 写 CONTROL_MODE=4 + VOLTAGE | ⚠️ 文档未明确 | 需咨询因时技术支持 |
| **速度力控模式** | 写 CONTROL_MODE=5 + FORCE + SPEED + POSITION | ⚠️ 文档未明确 | 需咨询因时技术支持 |

> ⚠️ **待确认**：电压模式和速度力控模式的 Modbus 映射方式需要联系因时技术支持确认。文档中只列出了 SETPOS、SETVEL、SETFORCE 三个动作寄存器，其余模式的触发方式尚不明确。

## 9. 风险评估与缓解

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| Modbus 侧波特率低导致响应慢 | **中** | 开局就设 115200；伺服模式下减少不必要的查询 |
| RS485 总线干扰/反射 | **低** | 用双绞屏蔽线 + 120Ω 终端电阻 + 菊花链拓扑 |
| 电压模式/速度力控模式不支持 | **中** | 先确认需求是否必需这两种模式；联系因时技术支持 |
| 6 个从站同时通信冲突 | **低** | Modbus RTU 天然是问答式，只有主机主动发起通信 |
| 24V 供电不足 | **低** | 选用 ≥6A 的电源，留 20% 余量 |
| 转换器故障导致单电机失联 | **低** | 转换器是独立模块，一个坏了不影响其他 |
| 长距离压降 | **低** | 24V 供电，线径 ≥0.5mm²，每 5m 补一个供电点 |

## 10. 实施步骤建议

### 第一阶段：单电机验证（预估 1 天）

1. 连接 1 个 AED-LA-92-12MR1 + 1 个电机

1. 在 RS485 总线上并联 2 个转换器
2. 设置不同从站地址（1 和 2）
3. 验证轮询通信不冲突
4. 测试波特率 115200 下的稳定性

3. 适配 ROS2 节点
4. 长时间运行稳定性测试
5. 伺服模式 6 电机高频轮询压力测试

### 第四阶段：文档与归档

1. 更新 README
